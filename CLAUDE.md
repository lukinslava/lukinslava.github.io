# Портфолио Славы Лукина — рабочие заметки

Памятка для следующих сессий: что это за репозиторий, какие решения уже приняты
и чего делать не надо. Пользовательская документация — в `README.md`.

## Что это

Статическая копия портфолио, снятая с Framer (`slavalukin.framer.website`) и
живущая на GitHub Pages: **https://lukinslava.github.io/**, репозиторий
`lukinslava/lukinslava.github.io`, источник — ветка `main`, папка `/docs`.
Рантайм Framer (React + Motion) сохранён, поэтому анимации и переходы работают
как на Framer, но сайт ни от чего не зависит: все картинки, видео, шрифты и
иконки лежат локально.

Аккаунт GitHub — **lukinslava**. Ключ по умолчанию на этой машине от другого
аккаунта, поэтому remote ходит через ssh-алиас `github-lukinslava`
(`~/.ssh/id_ed25519_lukinslava`). `gh` не установлен.

## Сборка

```bash
node tools/mirror.mjs                                    # скачать Framer → raw/ (в гите нет)
SITE_URL=https://lukinslava.github.io node tools/build.mjs   # raw/ + правки → docs/
node tools/serve.mjs                                     # локальный сервер, 4000
```

- `tools/content.mjs` — тексты (`contentEdits`) и CSS поверх Framer
  (`styleOverrides`, ~29 правил). Каждая правка обязана найтись хотя бы раз,
  иначе сборка падает — это защита от тихого расхождения с Framer.
- `tools/structure.mjs` — структура главной: удалённые и переделанные карточки,
  раздел «AI & side projects», вырезанный блок наград. Правки применяются
  одинаково к серверному HTML и к JS-модулю страницы, иначе React при гидрации
  вернёт старое.
- `tools/covers.mjs` — типографические обложки карточек в `tools/images/`.
- `tools/case/*.html` — самостоятельные страницы вне Framer; сборка копирует их
  в `docs/` как есть.
- `tools/case-media.mjs` — медиа для закрытого кейса (см. ниже).
- `tools/inject/` — интерактив поверх страницы вне React (тюнер наград).
- `tools/serve.mjs` — локальный сервер; `INJECT=a.css,b.js` подкладывает файлы
  в каждую страницу, чтобы примерять прототипы на живом сайте.

**Правило:** тексты и стили правим в `tools/`, не в `docs/` — пересборка
затирает `docs/` целиком.

## Принятые решения

**Структура главной.** Кейсы идут компактной сеткой: три карточки в ряд,
AI & side projects — пять (до 1100 px — по две, первая карточка ряда на всю
ширину). Сделано CSS поверх карточек Framer, без хирургии
по DOM: ссылки и анимации появления остаются живыми. Прототип раскладок —
`prototypes/cases-layout/` (десять вариантов, выбран «A · Compact grid»).

**Типографика.** Правило взято с педали Braun: у объекта один «логотип», всё
остальное — тихие подписи.
- В карточках опыта: название 28px почти чёрное; роль и описание 20px (как
  наборный текст в Core skills), роль темнее, описание светлее; даты и
  «and other from feb 2018» — 16px строчными.
- Описания карточек кейсов — 16px строчными, серые.
- **Важно:** сплошной перевод всего сайта в этот стиль пробовали
  (`prototypes/site-type/`) и **отклонили** — уменьшение кегля ломало вёрстку
  Framer (отступы списков, строки таблиц, нумерация). Если возвращаться, менять
  только цвет, начертание и регистр, а кегль и интерлиньяж не трогать.

**Награды.** Отдельного блока нет. Вместо него в блоке Experience оранжевая
кнопка питания, которая открывает «прибор» с 14-сегментным LCD: WDA 24,
WDA 25, Tagline Awards, Golden Site. Звуки — процедурные, из
`tools/inject/lib/ui-sounds.js` (код из github.com/mishanaer/sound, без
изменений, с указанием авторства). Сам блок Experience — светлый, не оранжевый.

**Новые карточки** (`newCards` в `tools/structure.mjs`) — копия готовой
карточки с новым текстом, ставится сразу после неё. Ссылка на страницу вне
Framer — только полным адресом (`https://lukinslava.github.io/…`), и у AI Match
тоже: `Link` Framer пропускает `./…` и `/…` через свой роутер, а он знает
только страницы Framer и превращает остальное в `./` (карточка AI Match какое-то
время вела на главную); голое `quack` он читает как домен. Минус: на локальном
сервере такие карточки ведут на живой сайт.

**Кэш модулей.** Модули Framer называются `<имя>.<хэш>.mjs`, и после наших
правок имя остаётся прежним. Браузер или CDN GitHub Pages тогда отдают новую
страницу со старым модулем, и React при гидрации выкидывает карточки, которых
модуль не знает (так пропала карточка Quack после первой выкладки). Поэтому сборка
переименовывает изменённые модули по хэшу содержимого и обновляет ссылки на
них (`tools/cache-bust.mjs`, шаг 5d). Правишь `docs/` руками — прогоняй
`bustCache` по изменённым модулям тоже.

**Видео-обложки** — `tools/inject/card-video.js` кладёт ролик поверх картинки
карточки (картинка остаётся постером), играет только пока карточка на экране,
при reduced motion не грузится. Ролики — в `tools/images/` рядом с постером,
список — `COVERS` в скрипте; `poster` — когда картинка карточки не похожа на
первый кадр ролика. Сейчас: Quack (`prototypes/notch-duck-cover/`) и AI Match —
`cover-ai-match-ui.mp4`, запись интерфейса от автора (12 с, кроп 16:10, подписи
на русском); при reduced motion остаётся тёмная типографическая обложка.
Прежняя версия с полем точек из `02-pain-funnel.mp4` заменена. Ролик с новым
содержимым кладём под новым именем, иначе кэш покажет старый. Проверять воспроизведение надо в Chrome: Chromium
из Playwright не умеет H.264.

**Обложки.** Типографические, как «Mindbox» и «2 → 5». У AI Match своя: тёмное
поле точек, 30 оранжевых равномерно по кадру, текст «AI Match» и
«5500+ designers → a pool of 30–60». Генератор — `prototypes/auf-cover/`,
экспорт в `tools/images/cover-auf-match.png` плюс уменьшенные `sdN` копии.

**Плашки «to add» на сайте не показываем.** Вопросы, на которые нет данных,
держим здесь, в «В работе», а на странице просто не пишем об этом.

**Тексты.** Английский на всём сайте, включая кейсы. Длинное тире вместо
дефиса. Цифры не выдумываем: если данных нет, пишем об этом прямо (например,
«инструмент ещё раскатывается, поэтому цифр по времени и наймам пока нет»).

## Кейс AI Match

Внутренний инструмент агентства, поэтому кадры интерфейса закрыты.

- **Шифрование.** `tools/case-media.mjs` берёт медиа из
  `~/Documents/auf-match-portfolio/media`, открытые файлы копирует как есть,
  кадры продукта шифрует AES-GCM; ключ — PBKDF2-SHA-256, 600 000 итераций.
  Пароль передаётся через `CASE_PASSWORD` и нигде не сохраняется. Результат —
  `tools/case/media/ai-match/`, сборка копирует его в `docs/assets/case/`.
  Текущий код — **1919** (выбран автором; честно сказано, что четыре цифры
  перебираются, это замедлитель, а не замок).
- **Открыто без кода:** текст, схемы воронки, публичная часть «Прожарочной».
  **Закрыто:** 16 кадров интерфейса и постеры роликов. Исключение — видео-обложка
  карточки на главной: запись интерфейса, автор решил показывать её открыто.
- Страница `tools/case/ai-match.html`, `noindex`, в sitemap не попадает.
- Прототип страницы — `prototypes/auf-case/` (в `.gitignore`: там symlink на
  медиа и постеры, которым не место в публичном репозитории).

**Как сняты кадры.** Демо-копия продукта в `~/Documents/auf-match-portfolio/`:
локальный Postgres, выдуманные данные, съёмка Playwright по сценариям. Для
портфолио всё переведено на английский: интерфейс — словарём на время съёмки
(`~/Documents/auf-match-portfolio/tools/i18n/`, ~700 строк плюс правила для дат
и порядковых), демо-данные — прямо в генераторах (`…/tools/data/`). Там же
ловушки, на которые уже наступали:
синтетические векторы подбора искали русские слова, а служебные значения
(`"смысл"`, `"лид"`, `"модель"`) нельзя переводить — на них завязана логика.

## Работа из облака

Облачная сессия видит только то, что лежит в репозитории. Это нормально для
текстов, CSS, структуры главной и страниц кейсов, но надо помнить:

- **`raw/` в гит не едет**, а домен Framer сетевая политика облака сейчас
  не пропускает, так что `mirror.mjs` и полный `build.mjs` в облаке не
  работают. Правки структуры главной можно прогнать прямо по `docs/` теми же
  функциями из `tools/structure.mjs` (так добавлена карточка Quack), но
  побайтно: страницы в `docs/` хранятся со смешанными переводами строк, и
  Python в текстовом режиме переписывает их целиком.
- **Скриншотов не будет:** `tools/shot.mjs` поднимает Google Chrome, которого в
  облаке нет. Проверять результат придётся по коду или уже после пуша, открыв
  живой сайт.
- **Материалов кейсов вне репозитория почти нет.** Демо-продукт AI Match
  (`~/Documents/auf-match-portfolio`, 1,3 ГБ) и исходники Little Museum
  (`~/Documents/museum case`, 154 МБ) живут только на машине автора: пересъёмка
  кадров возможна лишь локально. Готовые материалы Little Museum (слайды,
  экраны, ролики, текст, 73 МБ) лежат в `lukinslava/storage` (см. «В работе»)
  и клонируются в облако.
- **Прототип `prototypes/auf-case/`** намеренно в `.gitignore` и в облаке
  отсутствует; опубликованная версия страницы — `tools/case/ai-match.html`.
- **Код от кейса AI Match** в репозитории не хранится: его знает только автор.

Иначе говоря: правки текстов и вёрстки — хоть локально, хоть в облаке;
пересъёмка кадров и визуальная проверка — только локально.

## Проверка

- Смотреть результат **headless Chrome через CDP**, а не во встроенной панели
  браузера: там страницы грузятся с `visibilityState=hidden`, Framer
  останавливает видео и анимации появления выглядят сломанными. Готовый
  инструмент — `tools/shot.mjs`:

  ```bash
  node tools/shot.mjs http://localhost:4000/ el ".framer-bvvzdt" /tmp/cases.png
  node tools/shot.mjs http://localhost:4000/little-museum page /tmp/case.png 1440 0.4
  node tools/shot.mjs http://localhost:4000/ eval "document.title"
  ```

  Он сам прокручивает страницу (иначе Framer не покажет блоки) и в конце
  печатает ошибки страницы.
- После правок прогонять `node tools/build.mjs` и проверять, что сборка не
  ругается на ненайденные правки.
- Прототипы — в `prototypes/`, сервер: `node tools/serve.mjs 4100 prototypes`.
- Демо-продукт для пересъёмки кадров AI Match поднимается отдельно:
  `cd ~/Documents/auf-match-portfolio/tools && node --experimental-strip-types db.ts start`
  (Postgres на 5433), затем `cd ../demo && npx next dev -p 3100`. Сценарии
  съёмки запускаются через `tsx` из `demo/node_modules/.bin`, иначе падает
  импорт модулей продукта.
